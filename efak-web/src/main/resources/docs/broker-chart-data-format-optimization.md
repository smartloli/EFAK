# Broker图表数据格式优化报告

## 问题描述

用户要求根据 `cluster.js` 文件中 `updateBrokerMemoryChart` 函数渲染图表所需要的数据格式，调整 `/api/brokers/metrics/cpu-trend` 接口中返回的数据格式。

## 问题分析

### 前端期望的数据格式

从 `cluster.js` 中的 `updateBrokerMemoryChart` 函数可以看出，Chart.js 期望的数据格式为：

```javascript
{
  labels: ["时间1", "时间2", "时间3", ...],  // 时间轴标签数组
  datasets: [
    {
      label: "Broker 1",
      data: [10.5, 15.2, 12.8, ...]  // 与labels对应的数据点
    },
    {
      label: "Broker 2", 
      data: [8.3, 11.7, 9.5, ...]   // 与labels对应的数据点
    }
  ]
}
```

### 原始代码问题

原始的 `formatChartData` 方法存在以下问题：

1. **数据对齐问题**：每个broker的数据数组长度可能不一致，没有确保所有broker在相同时间点都有对应的数据
2. **时间排序问题**：时间标签没有进行排序，可能导致图表显示混乱
3. **时间格式问题**：数据库返回的时间格式（如 `2025-08-03T18:11:09`）对用户不够友好
4. **缺失数据处理**：没有正确处理某些时间点缺失数据的情况

## 修复方案

### 1. 重构数据处理逻辑

- 使用二维Map结构 `Map<String, Map<String, Double>>` 来存储时间序列数据
- 分别收集所有时间点和所有broker ID
- 确保每个broker的数据数组与时间标签数组完全对应

### 2. 添加时间格式化

- 新增 `formatTimeLabel` 方法，将ISO格式时间转换为用户友好的显示格式
- 格式：`MM-dd HH:mm`（如：`08-03 18:11`）

### 3. 处理缺失数据

- 对于某个时间点缺失的broker数据，使用 `null` 值填充
- Chart.js 能够正确处理 `null` 值，在图表中显示为断点

## 修复内容

### 文件：`BrokerMetricsController.java`

#### 1. 添加必要的import

```java
import java.util.HashSet;
import java.util.Set;
```

#### 2. 重构 `formatChartData` 方法

**主要改进：**

- **数据结构优化**：使用 `Map<String, Map<String, Double>> timeSeriesData` 存储时间序列数据
- **完整性保证**：确保每个broker的数据数组长度与时间标签数组长度一致
- **时间排序**：对时间标签进行排序，确保图表时间轴正确
- **缺失值处理**：对于缺失的数据点使用 `null` 值

#### 3. 新增 `formatTimeLabel` 方法

**功能：**

- 将ISO格式时间（`2025-08-03T18:11:09`）转换为友好格式（`08-03 18:11`）
- 提供异常处理，确保格式化失败时使用原始值

## 数据流程对比

### 修复前

